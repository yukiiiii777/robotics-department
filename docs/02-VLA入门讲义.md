# 02 · VLA 入门讲义

> VLA = Vision-Language-Action（视觉-语言-动作）大模型——给机器人的「大脑」。

## 一、VLA 是什么

一句话定义：**把相机看到的画面（视觉）、人说的话（语言）直接变成机器人动作（动作）的大模型**，中间不需要人工设计的规划模块。

### 与传统机器人开发的本质区别

| | 传统模块化流水线 | VLA 端到端 |
| --- | --- | --- |
| 结构 | 感知 → 规划 → 控制 → 执行，四段拼接 | 图像 + 指令 → 一个大模型 → 动作 |
| 开发方式 | 每个模块人工设计，换任务重写 | 采集示教数据训练，换任务微调 |
| 语义理解 | 无（指令要写死成代码） | 有（听得懂「把红色杯子递给我」） |
| 泛化能力 | 任务级泛化差 | 任务级泛化强，没训过的任务也能试 |

## 二、模型架构（翻译官比喻）

| 模块 | 干什么 | 类比 |
| --- | --- | --- |
| **VLM 骨干** | 视觉编码器 + 语言大模型，看懂图、听懂话；在互联网海量图文上预训练过 | 见过世面的「眼睛 + 耳朵」 |
| **动作头（Action Expert）** | 把「语言 token」翻译成「动作 token」（扩散 / 流匹配生成） | 专业「翻译官」 |
| **动作输出** | 连续的关节角度 / 末端位姿序列，按 10~50Hz 实时喂给机器人 | 机器人听得懂的「指令流」 |

## 三、训练流程（部门要做的事）

VLA 训练是**两级火箭**：

1. **预训练**：VLM 骨干用互联网级图文数据训练，天生「见过世面」（知道什么是杯子、红色、递）。
2. **真机数据微调**：部门核心工作——**数据闭环**：
   - 戴 PICO 眼镜，第一视角遥操 OpenFlex / PiPER 完成任务
   - 系统自动记录「画面 + 动作」成对数据（LeRobot 工作流）
   - RTX 4090 本地训练（ACT）或云端 A100 训练（Pi0.5）
   - 部署回真机跑 → 失败再采再训 → **数据飞轮，越用越聪明**

## 四、代表模型

| 模型 | 出品 | 特点 |
| --- | --- | --- |
| RT-2 | Google, 2023 | 首个 VLA，首创「动作当 token 输出」 |
| OpenVLA | 斯坦福等, 2024 | 开源 7B，学术界标配 |
| π0 / π0.5 | Physical Intelligence | 动作头用流匹配；**OpenFlex Ultra 官方支持部署** |
| ACT | 斯坦福 ALOHA | 轻量、双臂友好、入门首选，一张卡就能训 |

## 五、强在哪、弱在哪

**优势**：
- 语义泛化：听得懂人话，指令换成说法也能理解
- 任务级泛化：没见过的任务也能零样本 / 少样本尝试
- 跨本体迁移潜力：同一套框架可适配不同机器人

**短板（当前学界主攻方向）**：
- **数据饥渴**：真机数据贵 → 所以遥操数采才如此重要
- **高频精细控制难**：快节奏操作仍不如传统方法稳
- **推理延迟**：大模型跑不快 → 动作专家蒸馏、小模型化是热点

## 六、与导航的分层协作（官方推荐架构）

VLA **不建议**直接学长距离导航，推荐分层：

```
语言任务
 → 高层任务规划：选择目标区域和子任务
 → Nav2/NMPC：长程导航、避障、全局路径
 → VLA：到位后的底盘微调、升降、头部观察、双臂操作
 → ros2_control：关节、电机、舵轮底层闭环
```

即：**导航当「腿」，VLA 当「手 + 眼」，ros2_control 当「脊髓反射」**。

## 七、部门实操入口

详见 [Pi0.5 数采-训练-推理手册精要](04-OpenFlex-PI0.5数采训练推理手册精要.md)，核心流程：

1. OpenFlex 控制中心开 KAN 通讯
2. 三终端：相机录制服务 / VR 遥操服务 / 录制主程序
3. `lerobot-record-openflex.sh` 批量录制 episodes
4. LeRobot Studio 筛选数据
5. `torchrun lerobot-train` 训练（Pi0.5 需 A100 40G）
6. `HF_HUB_OFFLINE=1 lerobot-record` 真机离线推理
